# Release status

Release candidate `0.1.0` is implemented as a standalone local-first Windows desktop application. It has its own SQLite database, migrations, managed assets and user-data directory; the legacy frontend/backend repositories and production data were not modified.

Core scope is complete: secure Electron boundary; setup/login/RBAC and editable roles; users/password resets; customer, prescription, product, category and supplier management; barcode POS; immutable invoice snapshots; integer money; split/partial payments; debt, reversals, proportional returns/refunds; stock movements; purchase receiving and supplier ledger; cash sessions; expenses; audit history; bilingual RTL/LTR UI; database-driven dashboard; operational and analytical reports with filters/CSV; six native print/PDF templates; managed PDF/image attachments including expense receipts and store logo; full store legal/contact print fields; legacy JSON import with reconciliation; verified backup/restore of database and assets; configurable automatic backups, retention and visible failure notification; isolated maintenance CLI; and NSIS installer.

The dashboard provides current/previous KPIs, revenue/profit/sales trends, category/type/payment distribution, top products/categories, recent sales/payments, outstanding balances and low-stock alerts. Profit and COGS become unavailable instead of fabricated when imported historical cost is unknown. Optional appointments and lab orders were intentionally deferred under the brief's core-stability priority.

Verification on 13 September 2026: strict TypeScript passed; ESLint passed; 34 Vitest/React/database tests passed; both Electron lifecycle suites passed against development; the release suite passed against the unpacked packaged executable and against an actual silent installation in an isolated project folder. That suite covers Arabic RTL PDF output with a managed store logo, restored attachments, purchase payments, backup/restore and restart persistence. `npm audit --audit-level=low` found zero known vulnerabilities. The Windows installer completed with exit code 0.

External release gates: the installer is **not Authenticode-signed** because no publisher certificate was supplied, and physical-printer output cannot be certified without the shop's actual printer/driver/paper. PDF rendering and the native print path are automated and verified. Before live deployment, sign the installer, run a printer acceptance sheet on each target device, perform a supervised trial import against a copy of the real legacy export, and have the operator verify balances and opening stock. These are environment/operator gates, not placeholder application features.
